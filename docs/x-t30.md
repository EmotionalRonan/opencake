**判断**【推测】：#509 是在”读卡器”或默认模式下测的。X-T30 的 USB
静态拍摄能力只在”USB 视频拍摄
自动/固定”（即云台联机模式）下暴露，很可能从未被开源项目按这个模式完整测过。这正是实验的价值所在。

## 2. 实验路径：自研 Rust PTP

目标分三级，逐级推进，任何一级失败都有降级方案（§3）。

### 级别 1：识别与能力摸底

- 在每种连接模式下分别枚举：USB VID/PID（模式不同，PID 可能不同）、PTP
  `GetDeviceInfo`（支持的操作码、事件码、设备属性、厂商扩展字符串）、`GetStorageIDs`。
- 工具：Linux `lsusb -v` +
  `gphoto2 --summary --list-all-config`；Windows 用 WPD 枚举 +
  USBPcap/Wireshark 抓包；自研 `oc-ptp-probe` 命令行（`camera-ptp` crate
  的第一个产物）。
- 产出：`bench/cameras/fuji-x-t30/deviceinfo-<模式>.json`，作为相机兼容矩阵的第一条记录。

### 级别 2：触发快门

- 先试标准 PTP `InitiateCapture`（0x100E）。
- 再试 libgphoto2 `ptp.h` 中 `PTP_VENDOR_FUJI`
  下的拍摄相关操作码与属性（富士新机型走”设属性触发”的流程），只用级别 1
  里 DeviceInfo 实际声明的码。
- 若手头或能借到支持 X-T30 的云台（看云台厂商兼容表），用 USBPcap 或硬件
  USB 分析仪抓云台与相机之间的真实指令序列，重放验证。这是最可靠的路线。
- 同时测曝光属性读写（快门、光圈、ISO、曝光补偿）：固件明确开放了视频曝光，静态模式下是否可写待测。

### 级别 3：取回 RAF/JPEG

- 触发后监听 `ObjectAdded` 事件，或轮询 `GetObjectHandles` 对比差集，用
  `GetObject`/`GetPartialObject` 下载。
- “固定”模式下”照片不保存到卡”，说明图像可能留在相机缓存等待主机取走（类似其他机型的
  capture-to-SDRAM）【推测】。重点测这里：能否拿到完整 RAF、拿到的是 RAF
  还是 JPEG、单张耗时。
- 若只能触发、不能取图：走”USB 触发 + 无线/读卡回传”的混合方案（§3
  D2/D3）。
- 实时取景：X-T30 不会经 USB 给取景流。可选方案：micro-HDMI 干净输出 +
  UVC 采集卡，作为 `liveview` 的一个视频源（通用、零协议风险）。

### 驱动落地

- `camera-ptp/vendor/fuji.rs` 新增 `FujiGimbalMode`
  能力配置：`caps = REMOTE_CAPTURE (+ SET_PROPS?) (+ DOWNLOAD?)`，按级别
  1–3 的实测结果填写，UI 按能力灰显。
- 首发传输层：Linux `nusb` 最快出结果；Windows WPD
  紧随（用户主力系统若是 Windows 则先做 WPD）。
- 不依赖富士 SDK（其许可 §3.9 禁止置于 GPL/LGPL 下），全部基于协议实现。

## 3. 降级方案（按可行性排序）

| 方案                                                         | 可行性   | 延迟                       | 能拿到                      | 说明                                              |
|--------------------------------------------------------------|----------|----------------------------|-----------------------------|---------------------------------------------------|
| D1 读卡器 / USB 读卡器模式导入 + 热文件夹                    | 确定可行 | 分钟级，批量               | RAF + JPEG                  | 最稳；“准联机”：每 N 张插卡一次，导入即自动套配方 |
| D2 PC AutoSave（Wi-Fi）→ 目标文件夹 → 热文件夹               | 官方支持 | 较高，需在相机回放菜单发起 | 待测（JPEG 确定，RAF 待测） | 无线、免插卡；适合拍完一组集中出片                |
| D3 蓝牙自动传输到手机（Camera Remote）→ 手机同步到电脑文件夹 | 官方支持 | 秒到十几秒级【推测】       | 仅 JPEG（可能缩小）         | 只用于现场预览/客户选片，最终仍用 RAF             |
| D4 第三方 Wi-Fi SD 卡 → FTP/热文件夹                         | 视卡而定 | 秒级【推测】               | 视卡而定                    | 可选，兼容性需社区验证                            |
| D5 HDMI + 采集卡                                             | 确定可行 | 实时                       | 仅取景画面                  | 补实时取景，不传照片                              |

**推荐组合**：级别 2 成功则”USB 触发 + D1/D2 取片”；级别 3 成功则全 USB
联机。任何情况下 D1 都是保底，M2 交付前先把 D1 做到”插卡即出片”。

## 4. X-T30 RAF 作为首选测试素材

**为什么选它**：X-Trans IV 6×6 排列是 RapidRAW
当前最弱的环节（社区反馈去马赛克不如 Markesteijn）；26.1MP
体量适中，适合在 RTX 3060 / M1
上跑全管线基准；用户自己能持续产出人像和风光素材。

### 4.1 素材集（`bench/datasets/xt30/`，不入公开仓库，除非取得授权）

- `portrait/`：至少 30 张，覆盖肤色、逆光、夜景高
  ISO（3200–12800）、多人合影、眼镜。
- `landscape/`：至少 20 张，覆盖天空、树叶细节（X-Trans
  伪色/“蠕虫纹”高发区）、高反差。
- 每张 RAF+JPEG 同拍；记录胶片模拟、动态范围设置、RAW
  压缩方式（无压缩/无损压缩）。
- 人像素材需被摄者书面授权才可用于公开基准或训练；默认只做本地测试。

### 4.2 RAW 管线测试项

1.  解码正确性：所有压缩方式都能打开，白平衡/黑电平与相机 JPEG 一致。
2.  去马赛克质量：同一张 RAF 对比 RapidRAW
    现有算法、darktable/RawTherapee Markesteijn 3-pass（GPLv3
    代码可合法移植进 AGPL）。看锐度、彩噪、树叶伪色、皮肤纹理。
3.  速度：全尺寸解码 + 去马赛克耗时；内嵌 JPEG 尺寸与提取耗时。
4.  **预览一致性**：内嵌 JPEG 带胶片模拟色彩，与 RAW
    渲染结果不同。联机”2 秒预览”先用内嵌 JPEG，换成全分辨率 RAW
    渲染时会跳色。需要设计”胶片模拟近似 LUT”或在预览阶段就用 RAW
    快速半尺寸渲染，两种方案用此素材对比。

### 4.3 AI 模型槽测试项

1.  X-Trans 伪影对人脸检测/关键点/解析的影响：分别用 RAW 渲染和机内 JPEG
    跑 YuNet、MediaPipe、Selfie Multiclass，比较漏检和蒙版边缘。
2.  磨皮（频率分离基线 + ABPN）在 X-Trans
    皮肤纹理上的表现：是否把彩噪当瑕疵、是否放大”蠕虫纹”。
3.  抠图（BiRefNet/MODNet）发丝边缘、天空分割（风光）。
4.  每个槽在 RTX 3060 / M1 上的耗时回填模型卡 `performance`
    字段，设备名写 “X-T30 RAF 26MP”。

运行 `lsusb`，记下 `04cb:xxxx`。 - \[ \] 10.
相机屏幕显示什么（是否出现”联机/PC 连接”之类提示，能否继续拍照）。 - \[

`gphoto2 --auto-detect`、`gphoto2 --summary > summary-<模式>.txt`、`gphoto2 --list-all-config > config-<模式>.txt`，把文件发我。

### C. 云台模式触发（第二阶段，等我给出 `oc-ptp-probe` 工具后执行）

- [ ] 12. 连接模式设为”USB 视频拍摄 自动”，模式拨盘在静态拍摄位置，运行

- [ ] 13. 运行

- [ ] 15. 改为”USB 视频拍摄 固定”重复
  13–14；额外检查存储卡里是否没有新照片。
- [ ] 16. 运行
  `oc-ptp-probe props`，尝试读写快门、光圈、ISO、曝光补偿，记录哪些能改。

## 6. 决策门

- B 组完成后：确认哪种模式下 PTP 可见，定下级别 2 的实现方向。
- C 组完成后：
  - 能触发 + 能取图 → X-T30 进入”全 USB 联机”支持列表，写入兼容矩阵。
  - 能触发、不能取图 → 混合方案（USB 触发 + D1/D2）。
  - 不能触发 → D1 为主，D2/D3 辅助；X-T30 继续作为 RAW/AI
    测试主力素材，联机首发换一台官方支持联机的机身。
